# Architecture

## Pipeline overview

Each run of `main.py` executes a stateless, single-pass pipeline:

```
config / env vars
       │
       ▼
  resolve_universe(settings.UNIVERSE)
       │  list[str] — ticker symbols
       ▼
┌─────────────────────────────────────────┐
│  for each ticker  (stock_finder.run)    │
│                                         │
│  downloader ──► StockInfo               │
│       │          (historic_data,        │
│       │           TickerMetadata)        │
│       ▼                                 │
│  predicter ──► Forecast × 2            │
│       │         (2-year, 5-year)         │
│       ▼                                 │
│  analyzer ──► StockData                │
│                (all 20 fields)           │
│  notifier.notify(StockData)  ──► Telegram (per-ticker card)
│  stats_calculator.calculate(StockData)                     
└─────────────────────────────────────────┘
       │  list[StockData]
       ▼
  optimizer_dispatcher.optimize(stocks, budget)
       │  OptimizationResult
       │   ├─ risk_aware: Portfolio
       │   └─ profit_only: Portfolio
       ▼
  notifier.send_optimization_result(result) ──► Telegram (summary)
```

Every run is **stateless** — no database, no persistent cache. The only side-effects are:

- PNG chart files written during `analyzer.analyses` and deleted by `stock_finder.__clean_artifacts` at the end of each ticker loop.
- The portfolio-run counter incremented via `stats_calculator` (external HTTP call).
- Telegram messages sent via `notifier`.

## Ports / adapters layout

```
src/
├── logic/                      ← domain (no I/O, no framework deps)
│   ├── data/
│   │   ├── data.py             ← all value types (StockData, Forecast, …)
│   │   └── forecast.py         ← Forecast value object
│   ├── ports/
│   │   ├── predictor.py        ← Predictor protocol
│   │   └── optimizer.py        ← Optimizer protocol
│   └── stock_finder.py         ← orchestrator (application layer)
│
└── adapter/out/                ← infrastructure (all I/O)
    ├── analyze/analyzer.py     ← builds StockData, draws charts
    ├── download/downloader.py  ← yfinance
    ├── notify/notifier.py      ← Telegram (telepot)
    ├── optimization/
    │   ├── optimizer.py        ← GA backend (DEAP)
    │   ├── optimizer_cvxpy.py  ← CVXPY backend
    │   └── optimizer_dispatcher.py
    ├── parser/html_parser.py   ← counter HTML scraper
    ├── predict/
    │   ├── predicter.py        ← dispatcher
    │   ├── predicter_garch.py  ← GARCH backend
    │   └── predicter_prophet.py← Prophet backend
    ├── stats/stats_calculator.py
    └── stock_pick/stock_picker.py
```

Dependency direction: `adapter → logic` (never the reverse). `stock_finder` sits in `logic/` but imports adapter modules directly — it is the application layer, not the domain layer. A future refactor (§3 P2 in the roadmap) would move it to `src/application/`.

## Configuration

All settings live in `config/configuration.py` as a single `Settings(BaseSettings)` instance. Key algorithm selectors:

| Env var | Values | Default | Effect |
|---|---|---|---|
| `PREDICTER` | `garch`, `prophet` | `garch` | Which forecast backend `predicter.py` routes to |
| `OPTIMIZER` | `ga`, `cvxpy` | `ga` | Which portfolio optimizer `optimizer_dispatcher.py` routes to |
| `UNIVERSE` | `sp500`, `etf`, `de_etf`, `ishares`, `vanguard` | `etf` | Ticker list used in `main.py` |
| `APP_ENV` | `dev`, `prod`, `backtest` | `prod` | Profile overlay loaded from `config/profiles/{APP_ENV}.env` |

See `docs/configuration.md` (generated by `scripts/gen_config_docs.py`, §1 P2 in the roadmap) for the full settings reference.
